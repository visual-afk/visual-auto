# 00. 카드뉴스 자동화 시스템 개요

> 이 문서는 Claude Code가 **가장 먼저** 읽는 문서다.
> 개별 작업 지시는 01~06 문서를 참조한다.

---

## 1. 이 시스템이 푸는 문제

기존 상태: 카드뉴스를 "만드는" 코드는 있으나 **디자인 결(結)과 콘텐츠 결이 브랜드별로 분리되어 있지 않다.**

목표 상태:
- 브랜드 3종(살롱 / 트리필드 / 아카데미)이 **각각 다른 정보 종류·다른 구조·다른 디자인 토큰**으로 생산된다.
- 예진 매니저가 넣는 **타 업종 레퍼런스**(경제·재테크·과학·패션 등)를 자동으로 해부해서 **미용 버전으로 치환**한다.
- 디자인 값(컬러/폰트)은 코드에 흩어지지 않고 **단일 출처(05 결정시트)** 에서만 온다.

---

## 2. 시스템 3대 원칙 (모든 판단의 기준)

| # | 원칙 | 의미 |
|---|---|---|
| P1 | **레퍼런스에서 훔치는 것은 "구조와 리듬"이지 "디자인 값"이 아니다** | 장수·역할 시퀀스·후킹 공식·정보 밀도·강조 리듬만 차용. 컬러·폰트·로고·사진톤은 폐기하고 브랜드 토큰으로 치환. |
| P2 | **브랜드는 "말투"가 아니라 "정보의 종류"로 구분된다** | 같은 주제라도 살롱은 *심미 원리*, 트리필드는 *모발 과학*, 아카데미는 *운영 수익*으로 각도를 튼다. 말투는 그 결과물일 뿐. |
| P3 | **디자인 값은 하드코딩 금지** | 코드·프롬프트·기획 단계에서는 역할 토큰명(`강조색`, `본문색`, `표제서체`)만 사용. 실제 값은 05 결정시트에서 주입. |

---

## 3. 파이프라인

```
[1] 레퍼런스 수집          예진 매니저 → /references/inbox/
       ↓                    (이미지 + 최소 메타 3필드)  … 02 문서
[2] 레퍼런스 해부          이미지 분석 → reference_dna.json
       ↓                    (구조/레이아웃/타이포/강조/톤/비주얼 DNA)  … 02 문서
[3] 주제 변환              타 업종 주제 → 브랜드별 미용 토픽 후보
       ↓                    (도메인 라우팅 + 4단계 치환)  … 02 문서
[4] 카드 기획              cardnews_plan.json 생성
       ↓                    (카드 역할 시퀀스 + 빈 슬롯)  … 03 문서
[5] 카피 생성              슬롯 채우기 (브랜드별 프롬프트)
       ↓                                                  … 06 문서
[6] 렌더링                 토큰 주입 → 이미지 출력
       ↓                    (04 토큰 스키마 + 05 결정시트 값)
[7] 자동 QC                반려 or 통과 → /output/
                                                          … 06 문서
```

각 단계는 **독립 실행 가능**해야 한다. (2번만 재실행, 5번만 재생성 등)

---

## 4. 폴더 구조 (권장)

```
/docs/cardnews/            ← 이 문서 세트 (공통 + 브랜드 접미사 문서)
/cardnews/                 ← ★데이터 루트 유일 위치. 루트에 references/, brand/, plans/ 를 새로 만들지 말 것
  /references/
    /inbox/{brand}/        ← 예진 매니저가 던지는 원본 (분석 전) — salon / trifield / academy 하위폴더
    /dna/{brand}/          ← reference_dna.json (분석 완료)
    /retired/              ← 3회 이상 사용됐거나 폐기된 레퍼런스
  /brand/
    salon.json             ← 01 문서의 브랜드 규칙을 기계가 읽는 형태 (각 브랜드 전담 창이 관리)
    trifield.json
    academy.json
  /tokens/
    token-schema.json      ← 04 문서 (역할만, 값 없음)
    token-values.json      ← 05 결정시트 확정 후 생성 ★유일한 디자인 값 출처
  /plans/                  ← cardnews_plan.json (plan_id에 브랜드 포함, 평면 배치)
  /photos/{plan_id}/       ← 예진 매니저가 찾은 사진 (카드 번호 파일명: 0.jpg, 3.png …)
  /output/
    /draft/  /passed/  /rejected/
```

> 2026-08-19 통합: 초기 버전의 루트 `references/`·`brand/`·`plans/` 는 `cardnews/` 아래로 이동 완료.
> 브랜드 창(세션)들은 반드시 위 경로만 사용한다.

---

## 5. 문서 맵 · 읽는 순서

| 단계 | 읽어야 할 문서 |
|---|---|
| 레퍼런스 등록·해부 | **02** |
| 주제 잡기 | **01 → 02** |
| 카드 기획 | **01 → 03** |
| 카피 생성 | **01 → 03 → 06** |
| 렌더링 | **04 → (token-values.json)** |
| 검수 | **06** |

- **01** 브랜드 매트릭스 — 누구에게 무슨 정보를 주는가
- **02** 레퍼런스 해부 및 변환 — 타 업종 레퍼런스를 미용으로 바꾸는 엔진
- **03** 카드 구조 스키마 — 카드 역할·시퀀스·JSON 슬롯·글자수 제약
- **04** 디자인 토큰 스키마 — 역할 토큰 정의 (값 없음)
- **05** 디자이너 결정시트 — 토큰에 값을 채우는 유일한 문서
- **06** 생성 프롬프트 규격 & QC — 실제 프롬프트 원문 + 자동 검수 룰

브랜드별 문서는 `-academy` / `-salon` / `-trifield` 접미사로 분리한다.
(예: `01-brand-academy.md`) 각 브랜드는 별도 세션(창)에서 작업한다.

---

## 6. 현재 미확정 항목 (채워야 코드가 완성됨)

| 항목 | 상태 | 결정 주체 |
|---|---|---|
| 렌더링 방식 (HTML→PNG / PPT / Figma API / 디자인툴 수작업) | **미정** — 단, visual-auto-web에 satori 기반 렌더러 기존재 | 실장 |
| 컬러·서체 실제 값 | **미정** (역할 토큰만 존재) | 디자이너 (05 시트) |
| 브랜드별 레퍼런스 실물 | **입력 대기** | 예진 매니저 |
| 카드 사이즈 (1:1 / 4:5 / 9:16) | **미정** | 실장 |

이 4개가 미정인 상태에서도 01~03, 06은 그대로 작동한다. 04·05만 값 주입을 기다린다.

## 7. 기존 코드와의 관계 (visual-auto-web)

이 문서 세트는 백지에서 출발하지 않는다. `visual-auto-web`(origin/main 및 `yejin/cardnews-*` 브랜치)에 이미 있는 것:

| 자산 | 위치 | 이 문서 세트와의 관계 |
|---|---|---|
| 카드 타입·파서 (`cover/point/cta`, 3~8장) | `visual-auto-web/lib/cardnews/cards.ts` | **03 문서의 역할 시퀀스가 이 렌더 타입으로 매핑**된다 |
| 브랜드 프레임 토큰 (`card_frames` 테이블) | `visual-auto-web/lib/cardnews/frames.ts`, 마이그레이션 0020 | **05 결정시트 값의 런타임 주입 지점** (token-values.json ↔ card_frames 동기화) |
| 레퍼런스 이미지 학습 (Vision DNA 추출·취합) | `yejin/cardnews-references` 브랜치 `lib/cardnews/styleExtract.ts` | **02 문서의 해부 엔진 구현체** — reference_dna.json 스키마의 원형 |
| 브랜드 컨셉 문서 | `visual-auto-web/knowledge/cardnews/concept-아카데미.md` 등 | 01 문서의 요약본. **충돌 시 01 문서가 SSOT** |
| 카드 생성 프롬프트 (구분자 출력) | `visual-auto-web/prompts/card-news-*.md` | 06 문서가 브랜드별로 확장. **JSON 모드 금지, 구분자 포맷 유지** |
