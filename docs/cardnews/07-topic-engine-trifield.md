# 07-트리필드. 주제 엔진 — 모발 뉴스데스크 (365일 자동 기획)

> 트리필드의 소재 공급 시스템. 02(레퍼런스 치환)가 "구조"의 입구라면, 이 문서는 "소재"의 입구다.
> 원리: **머리카락은 고정 지식이라 그냥 두면 3개월이면 바닥난다.** 그래서 ① 지식 전체를 신문처럼 14개 '면'으로 쪼개고 ② 고정 지식을 뉴스로 바꾸는 6개 프레임을 곱하고 ③ 외부 시계 5개를 물려 매일 새 소재가 들어오게 한다.
> 기계용: `cardnews/topics/trifield-topic-bank.json` (은행) · `cardnews/topics/trifield-schedule.{json,md}` (편성표) · `scripts/cardnews-topic-schedule.ts` (편성기)

## 4. 외부 시계 5개 (소진 방지 장치)

| 시계 | 주기 | 동작 |
|---|---|---|
| 계절 캘린더 | 자동 | 은행 소재의 `months` 필드 — 해당 월에 자동 우선 편성 (장마 곱슬=6·7월, 가을 탈모=9~11월, 겨울 정전기=12~2월). 매년 재활용 |
| 신제품·신기술 | 상시 | 예진 매니저가 은행에 소재 추가 (D06/D07) → 목요일 라이브 슬롯에서 교체 |
| 논문·특허·규제 | 월 1회 | 월간 스캔 후 D12에 소재 추가 |
| 트렌드·이슈 | 상시 | 셀럽·틱톡 셀프시술 → 검증 콘텐츠로 D05/D08에 추가 |
| 자사 데이터 | 주 1회 | 지점 질문 로그·클레임·시술 통계 → **남들이 절대 못 쓰는 소재.** F6(사건화)로 |

라이브 소재 교체 방법: 은행에 entry 추가 후 그 날짜의 schedule.json 행을 손으로 바꾸거나, 그냥 그날 발행에서 교체 (편성표는 가이드지 족쇄가 아니다).

## 5. 자동화 파이프라인

```
[은행] trifield-topic-bank.json (142 소재, 예진 매니저가 계속 추가)
   ↓  node scripts/cardnews-topic-schedule.ts --from YYYY-MM-DD --days 365
[편성표] trifield-schedule.json + .md (365일, 결정론적 — 같은 입력이면 같은 출력)
   ↓  매일 08:00 KST (GitHub Actions cardnews-daily-topic)
[알림] Google Chat: 오늘의 면/소재/프레임/팩트시드 + 검증 필요 여부
   ↓  예진 매니저 or 자동 생성 잡
[기획] 02 STEP 3~4 (경계 판정 + fact_basis 3개 확정) → cardnews/plans/*.json
   ↓
[카피] 06 프롬프트 → [렌더] → [QC]
```

- 편성기는 AI를 안 쓴다 (결정론적 로테이션). AI가 개입하는 건 [기획]의 fact_basis 조사와 [카피]부터.
- `verify: true` 소재는 알림에 ⚠️가 붙는다 — **fact_basis 3개 확정 전 발행 금지** (01 §4).
- 은행 소재를 추가·수정하면 편성기를 재실행한다. 과거 날짜는 안 바뀌고 미래만 재배치된다(같은 --from 기준).

## 6. 운영 규칙

- 편성표의 소재가 마음에 안 들면 그날 것만 바꾸고 편성표 재생성은 하지 않는다 (다음 재생성 때 은행 순서가 반영됨).
- 같은 소재 재등장 최소 간격: 풀 크기에 따라 자동 (주력면 D06도 12소재 × 주1회 = 12주 간격).
- 3개월마다 은행 점검: 사용 로그 보고 반응 나쁜 소재 은퇴(`retired: true` 추가), 새 소재 보충. 지도(14면)는 고정, 소재만 순환.
