# 07-트리필드. 주제 엔진 — 모발 뉴스데스크 (365일 자동 기획)

> 트리필드의 소재 공급 시스템. 02(레퍼런스 치환)가 "구조"의 입구라면, 이 문서는 "소재"의 입구다.
> 원리: **머리카락은 고정 지식이라 그냥 두면 3개월이면 바닥난다.** 그래서 ① 지식 전체를 신문처럼 14개 '면'으로 쪼개고 ② 고정 지식을 뉴스로 바꾸는 6개 프레임을 곱하고 ③ 외부 시계 5개를 물려 매일 새 소재가 들어오게 한다.
> 기계용: `visual-auto-web/lib/cardnews/topic-banks/trifield.json` (은행) · Supabase `cardnews_topics` (편성 SSOT) · `visual-auto-web/lib/cardnews/topic-engine.ts` (편성기)

## 5. 자동화 파이프라인 (visual-auto-web 앱 내장)

```
[은행] visual-auto-web/lib/cardnews/topic-banks/trifield.json (154 소재, 예진 매니저가 계속 추가)
   ↓  매일 08:50 KST 크론 /api/cron/extend-cardnews-topics (lib/cardnews/topic-engine.ts — 결정론 로테이션)
[편성 테이블] Supabase cardnews_topics ★SSOT — 90일 앞까지 append-only 시드
   ↓  앱 /calendar 에 초록 칩으로 표시                    ↓  best-effort 내보내기
[콘텐츠 캘린더] 클릭 → 주제 수정 모달(TopicEditor)      [구글캘린더] 초록 이벤트 (보기 전용)
   ↓  크론이 앞으로 7일치 초안 자동 생성 (헤드라인·카드 5장·캡션·해시태그 — 회당 5개)
[카드뉴스 초안] card_news(draft, 자동) — 주제 모달 "만든 카드뉴스 열기"로 진입. 수동 "이 주제로 만들기"도 동일 코어(lib/cardnews/draft-topic.ts)
```

- 편성 엔진은 AI를 안 쓴다 (결정론적 로테이션). AI가 개입하는 건 카피 생성부터.
- **사람의 일은 두 가지뿐**: ⚠️ 수치 검증(팩트 확정 체크) + 스튜디오에서 다듬고 발행. 헤드라인·카드·캡션은 자동으로 준비된다.
- `verify: true` 소재는 캘린더에 "팩트 확인 필요" 배지 — **팩트 확정(체크) 전 발행 금지** (01 §4).
- 은행 소재를 추가하면 다음 크론부터 미래 편성에 반영된다. 이미 테이블에 있는 날짜는 시드가 건드리지 않는다.
- 최초 시드: 0028 마이그레이션 실행 → 배포 → `curl -H "Authorization: Bearer $CRON_SECRET" https://…/api/cron/extend-cardnews-topics` 1회.

## 5-1. 사용자 수정 흐름 (앱 콘텐츠 캘린더 = SSOT)

콘텐츠 캘린더(/calendar)의 초록 칩을 클릭하면 주제 편집 모달이 열린다.
필드: `소재 / 프레임(6종) / 팩트시드 / 헤드라인초안 / 말풍선 / 레퍼런스 영상 / 팩트확정 / 상태 / 메모`
상태는 제작 파이프라인: **기획중 → 레퍼런스 → 촬영완료 → 업로드완료** (+건너뜀). 수정 모달의 상태 셀렉트로 바꾼다.

### 달력에서 직접 조작 (칸반 보드는 폐기 — 2026-08-27 대표 피드백)
- **날짜 이동**: PC 달력에서 칩(일정·주제)을 끌어 다른 날짜에 놓으면 옮겨진다. 한 날짜에 주제 여러 개 가능 (0029에서 하루 1개 제약 제거). 모바일은 수정 창에서 날짜 변경.
- **선택 모드**: 헤더 "선택" 버튼 → 칩·행 클릭으로 고르고 "선택 삭제" (전체 선택 지원, 일정+주제 동시). 삭제는 영구 — 자동 편성이 되살리지 않는다.
- **주제 편성 버튼**: 크론을 기다리지 않고 즉시 시드. 전체 삭제 후 누르면 오늘부터 현재 은행으로 새로 짜진다 (새 은행 반영 절차).

| 하고 싶은 것 | 방법 |
|---|---|
| 그날 주제 바꾸기 | 소재·프레임·팩트시드 수정 → 저장 (구글캘린더에도 반영) |
| 헤드라인·말풍선 미리 잡아두기 | 헤드라인초안·말풍선 입력 → 생성 시 재료로 주입 |
| 그날 발행 건너뛰기 | 상태를 `건너뜀` → 구글캘린더 이벤트 삭제 |
| 주제 일괄 갈아엎기 | 달력 "선택" → 전체 선택 → 선택 삭제 → "주제 편성" |
| 라이브 소재로 교체 | 목요일 행의 소재·팩트시드를 신제품/트렌드로 덮어쓰기 |
| 팩트 확인 완료 표시 | "팩트 확인 완료" 체크 |
| 카드뉴스 만들기 | 모달의 "이 주제로 만들기" → 초안 생성 후 스튜디오 이동, 주제는 완료 처리 |

- 시드는 **append-only**: 이미 있는 날짜는 절대 덮어쓰지 않는다. 사용자 수정이 항상 이긴다.
- **삭제는 영구다** — 시드는 마지막 편성일 *이후*만 추가하므로 지운 날짜를 되살리지 않는다.
- 구글캘린더는 보기 전용 내보내기다. 이벤트를 캘린더에서 직접 고치지 말 것 (다음 저장 때 앱 값으로 되돌아감).

## 5-2. 홍보 자아 금지 (2026-08-27 대표 지시)

- 주제 편성·카드 카피는 **정보 콘텐츠다.** 브랜드·제품 언급, 구매·예약 유도 문장 금지 — 브랜드는 톤으로만 드러난다.
- 구현: 주제 기반 생성(`/api/card-news` topic 경로)은 마케팅 지식(branch-트리필드.md 등)을 주입하지 않고 **카드뉴스 컨셉 파일만** 쓴다. `prompts/card-news-topic.md`에 홍보 금지 조항 명문화.
- 은행(`trifield.json`)에도 홍보 소재를 넣지 않는다. 제품 이야기는 D06(성분·제품)처럼 **소비자 관점 정보**로만.

## 6. 운영 규칙

- 편성표의 소재가 마음에 안 들면 그날 것만 바꾸고 편성표 재생성은 하지 않는다 (다음 재생성 때 은행 순서가 반영됨).
- 같은 소재 재등장 최소 간격: 풀 크기에 따라 자동 (주력면 D06도 12소재 × 주1회 = 12주 간격).
- 3개월마다 은행 점검: 사용 로그 보고 반응 나쁜 소재 은퇴(`retired: true` 추가), 새 소재 보충. 지도(14면)는 고정, 소재만 순환.
