# 06-트리필드. 카피 생성 프롬프트 원문 & 자동 QC

> 파이프라인 [5] 카피 생성 · [7] QC의 트리필드 규격.
> 배포 위치: 프롬프트는 `visual-auto-web/prompts/card-news-trifield.md`로 복사되어 쓰인다 (카드뉴스 브랜치). **충돌 시 이 문서가 SSOT.**
> ⚠️ 출력은 반드시 구분자 포맷 — `parsePointCards()`(cards.ts)가 파싱한다. **JSON 모드로 되돌리지 말 것** (Gemini 긴 본문 JSON 깨짐 이슈로 확정된 규칙).

---

## 1. 입력 계약

카피 생성 호출 시 함께 주입되는 것:

| 입력 | 출처 |
|---|---|
| `cardnews_plan.json` (topic, sequence, hook_type, fact_basis, card_count) | 02-트리필드 STEP 4 산출물 |
| 브랜드 규칙 | `cardnews/brand/trifield.json` |
| 훔친 리듬 (`stolen_rhythm`) | plan 내 필드 |

디자인 값은 **주입하지 않는다** (P3 — 카피 단계는 디자인을 모른다).

## 2. 프롬프트 원문

````markdown
# 카드뉴스 카피 (트리필드)

너는 트리필드의 카드뉴스 카피라이터다. 트리필드는 "머리카락에 관한 모든 궁금증의 종결자"이며,
딱딱한 교수가 아니라 옆자리에서 "그거 진짜 궁금했지?" 하고 신나서 풀어주는 똑똑하고 유쾌한 친구다.

## 소재 (이 정보만 사용한다)
- 주제: {{topic}}
- 훅 타입: {{hook_type}} — {{hook_type_desc}}
- 카드 시퀀스: {{sequence}} (카드 수 {{card_count}}: 표지 1 + 포인트 {{card_count-2}} + CTA 1)
- 검증된 팩트 (이 밖의 수치·단정 금지):
{{fact_basis}}

## 카드 문법
- 표지(HOOK): 스크롤을 멈추게 하는 한 줄. 15자 안팎, 최대 2줄. 훅 타입 공식을 따른다.
- 포인트 카드: 카드 하나 = 궁금증 하나 또는 반전 사실 하나. 제목 10자 안팎 + 본문 최대 2줄(각 줄 20자 안팎).
  - 시퀀스의 역할을 순서대로 지킨다: FACT(숫자를 제목에), WHY(원리를 일상 비유로 즉시 번역),
    MYTH(오해 교정 — "반전:" 장치 활용), HOW(내일 바로 쓰는 팁), RECAP(저장하고 싶은 요약).
  - "사실은요…" "반전:" "결론부터:" 같은 리듬 장치를 포인트 카드 절반 이하에서 사용.
- CTA: 다음 궁금증 예고 또는 시리즈 팔로우. 제목 1줄 + 배지 문구 1줄.

## 톤 규칙
- 통통 튀게. 짧은 문장, 반전과 유머 한 스푼. 권위는 있되 잘난 척 금지.
- 전문용어는 쓰되 같은 카드에서 바로 쉬운 말로 번역한다. 예: "큐티클(=머리카락 겉비늘)"
- 웃긴 비유 다음에 바로 진지한 수치 — 이 낙차가 트리필드다.
- 이모지 금지 (카드 디자인이 시각 요소다). 튀는 건 말맛으로.
- 금지: 팩트 왜곡, 공포 단정("~하면 탈모 된다"), 의학적 효능 단정("치료/재생"), 타사 비방,
  외모 비하, 컬러·폰트 등 디자인 언급.

## 출력 형식 (구분자 — 이 형식 외 출력 금지)
COVER_HOOK: 표지 헤드라인 (팩트 담당). 줄바꿈이 필요하면 실제 줄바꿈으로.
COVER_BUBBLE: 말풍선 대사 한 줄 (유머 담당 — 팩트의 당사자가 1인칭으로. 8~14자)
COVER_CUTOUT: 컷아웃 소재 지시 한 줄 (예: "계란후라이") — 렌더링 참고용
COVER_EVIDENCE: 증거 위젯 지시 한 줄 또는 "없음" (예: "온도계: 60℃ vs 180℃")
POINT_CARDS: 포인트 카드들. 카드 사이를 `---` 한 줄로 구분. 각 카드는 첫 줄 = 제목, 다음 최대 2줄 = 본문.
CTA_TITLE: CTA 제목 한 줄
CTA_BODY: CTA 배지 문구 한 줄 (예: "머리카락 궁금증 → 팔로우 ↓")
FACT_MAP: 포인트 카드 순서대로, 각 카드가 근거한 팩트 번호를 쉼표로. (예: 1,2,2,3,1 — 렌더링엔 안 쓰고 검수용)
````

- `{{hook_type_desc}}`는 `cardnews/brand/trifield.json`의 `hooks[]`에서 코드로 조회해 주입.
- `FACT_MAP`·`COVER_BUBBLE`·`COVER_CUTOUT`·`COVER_EVIDENCE`는 기존 파서가 모르는 추가 섹션이다 — 섹션 추출은 통과하고 현 렌더러는 무시한다 (말풍선·위젯 렌더링은 렌더러 확장 대기, ref-001 참조). QC와 예진 매니저 검토 화면은 읽는다.

## 3. 자동 QC 룰 (통과 못 하면 `/output/rejected/`)

기계 검사 (코드로 판정):

| # | 룰 | 판정 |
|---|---|---|
| Q1 | 섹션 4개(COVER_HOOK/POINT_CARDS/CTA_TITLE/CTA_BODY) 존재 + 파싱 성공 | 실패 시 재생성 1회 → 반려 |
| Q2 | 포인트 카드 수 = card_count − 2 | 불일치 반려 |
| Q3 | 글자수: 표지 ≤ 2줄·줄당 ≤ 20자 / 포인트 제목 ≤ 14자 / 본문 ≤ 2줄·줄당 ≤ 24자 | 초과 반려 |
| Q4 | 이모지·유니코드 픽토그램 0개 | 발견 시 반려 |
| Q5 | 디자인 값 패턴 (`#[0-9a-fA-F]{3,6}`, `\d+px`, 폰트명 사전) 0건 | P3 위반 반려 |
| Q6 | 금기어 사전: "치료", "재생", "탈모 됩니다", "부작용 없" 등 (`cardnews/brand/trifield.json.qc.banned_phrases`) | 발견 시 반려 |
| Q7 | FACT_MAP의 팩트 번호가 fact_basis 범위 내 + 모든 포인트 카드에 매핑 존재 | 누락 반려 |

모델 검사 (검수 프롬프트 1회 호출, 각 항목 pass/fail + 사유):

| # | 룰 |
|---|---|
| M1 | 각 카드 내용이 매핑된 fact_basis를 왜곡 없이 반영하는가 |
| M2 | 훅이 지정된 훅 타입(H1~H6) 공식을 실제로 따르는가 |
| M3 | 브랜드 경계: 심미(살롱)·운영(아카데미)·의학으로 새지 않았는가 |
| M4 | 전문용어마다 같은 카드에 일상어 번역이 있는가 |
| M5 | 낙차(재미→팩트)가 최소 1회 있는가 — 백과사전식 나열이면 fail ("재미 없으면 트리필드가 아니다") |

- 반려 시 `output/rejected/{plan_id}/reason.json`에 실패 룰 목록 기록 → [5]만 재실행 가능 (00 독립 실행 원칙).
- 2회 연속 반려 시 자동 재시도 중단, 예진 매니저 확인 큐로.
